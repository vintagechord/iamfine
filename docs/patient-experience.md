# 환자 중심 사용성 개선

조사일: 2026-09-07. 하이디의 공개 서비스 설명과 대한신장학회 자료를 검토했다. 앱 계정을 이용한 내부 화면 실사용 평가는 수행하지 않았다.

## 하이디에서 적용한 장점

| 공개 자료에서 확인한 기능 | IamFine 반영 방향 |
| --- | --- |
| 기본 정보와 질환 상태에 맞춘 안내 | 기존 치료 정보에 식사 불편 증상, 부드러운 식사 선호, 피할 재료를 함께 반영 |
| 식품 찾기와 식사 기록 | 세부 음식명·다른 표기·오타·같은 종류 검색, 선택한 음식만 기록 |
| 기록을 한 곳에 모아 변화 확인 | 홈·식단·기록·내 정보 하단 이동, 메뉴에서 달력·리포트·치료 일정 접근 |
| 전문가가 제공하는 교육 정보 | 최근 2개월의 기사와 병원·암센터 원문을 날짜·출처와 함께 표시 |

정보량을 줄이기 위해 긴 설명은 펼쳐 보기로 제공하고, 모바일 조작 영역은 44px 이상으로 맞춘다. 알림은 자동으로 넘기지 않으며 필요한 만큼 더 볼 수 있다.

하이디는 신장질환 대상 서비스다. 해당 앱의 칼륨·인·단백질·수분 목표나 위험도 계산을 암 환자에게 그대로 적용하지 않는다. 신규 증상별 안내는 미국 국립암연구소(NCI)의 환자용 식사 안내를 참고했다. 식품명 목록은 영양성분 데이터베이스가 아니며, 비슷한 음식 검색 결과는 동일 음식·동일 영양값을 뜻하지 않는다. 재료 제외는 메뉴명 기준이므로 실제 재료·양념·교차 접촉 확인을 대신하지 않는다.

## 운영 확인

- 음식 검색: 정확한 이름, 다른 표기, 띄어쓰기·섭취량, 오타, 미등록 세부 메뉴, 무관한 검색어를 확인한다. 직접 추가 시 원래 입력을 유지한다.
- 맞춤 정보: 한국 날짜 기준 2개월 경계, 월말·윤년, 미래·무효·미상 날짜 제외, 원문/재전송 및 유사 제목 중복, 브라우저 캐시 재필터링을 확인한다.
- 개인화: 설정 저장·해제, 재방문 반영, 재료 제외와 증상 충돌, 기존 치료 안내 유지 여부를 확인한다.
- 모바일: 하단 메뉴 활성 상태, 긴 음식·기사 제목, 큰 글자, 메뉴 닫기와 키보드 포커스, 화면 아래 저장 버튼 접근을 확인한다.
- 배포 전 전체 ESLint, TypeScript 빌드, 네이티브 Node 단위 검증과 주요 경로 응답을 확인한다. 새 패키지나 데이터베이스 스키마 변경은 필요하지 않다.
