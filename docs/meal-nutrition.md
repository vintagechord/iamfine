# 식단별 예상 영양 구성

식단 추천 팝업의 **영양 구성**을 펼치면 선택한 한 끼의 예상 열량, 탄수화물·단백질·지방의 양과 열량 비율을 확인할 수 있습니다. 대표 성분 자료에 계산용 분량을 적용한 추정치이며, 실제 섭취량이나 개인별 권장량을 뜻하지 않습니다.

식단 관리의 **기록일 추천 식단 팝업**, **식사 기록 살펴보기 → 영양 참고 정보**, 리포트의 **최종 추천 식단 → 영양 구성**도 같은 `MealNutrition`을 사용합니다. 각 화면에서 끼니별로 펼쳐 확인하며, 해당 화면의 최종 추천 식단을 계산합니다. 실제 식사 기록을 분석한 수치는 아닙니다.

## 데이터와 출처

공식 자료는 2026-09-08에 내려받아 필요한 항목을 선별했습니다. 내려받은 날짜와 자료 자체의 기준일은 구분하며, 각 행의 `source.referenceDate`를 유지합니다. 예를 들어 USDA SR Legacy 항목에는 `2018-04`, 식약처 항목에는 해당 행의 `2023-06-26`, `2023-07-07`, `2024-12-27` 등이 기록되어 있습니다.

| 파일 | 포함 범위 | 보존하는 식별 정보 |
| --- | --- | --- |
| [nutritionIngredients.ts](../src/lib/nutritionIngredients.ts) | 재료·대표 식품 75개 항목: USDA SR Legacy 62개, 식약처 12개, 계산용 물 1개 | `source.name`, `foodCode`, `description`, `referenceDate`, `url` |
| [nutritionDishes.ts](../src/lib/nutritionDishes.ts) | 식약처 조리식품을 음식명에 매핑한 30개 항목 | 같은 출처 필드. 별칭이 같은 원본 식품코드를 공유할 수 있음 |
| [mealNutritionRecipes.ts](../src/lib/mealNutritionRecipes.ts) | 음식별 계산용 재료와 g 단위 분량, 명시적으로 등록한 별칭 | 재료 키와 가정 분량. 원본 성분값과 분리 |

식약처 항목은 [식품영양성분 데이터베이스](https://various.foodsafetykorea.go.kr/nutrient/general/food/firstList.do), USDA 항목은 [FoodData Central 자료 내려받기](https://fdc.nal.usda.gov/download-datasets/)에서 확인합니다. 코드에는 식약처 식품코드와 USDA FDC ID를 그대로 보관합니다. 예시는 식약처 쌀밥 `D301-022000000-0001`, 달걀찜 `D307-317040000-0001`, 생 흑미 `R101-008000701-0000`, USDA 익힌 새우 `175180`입니다. 화면의 출처에서도 해당 대표 식품명과 식별 코드를 확인할 수 있습니다.

**100 g당 열량(kcal), 탄수화물(g), 단백질(g), 지방(g)이 모두 있는 자료만 사용합니다.** 100 mL 기준 행을 100 g으로 간주하지 않으며, 누락값을 0으로 채우지 않습니다. 계산 단계에서도 네 값이 모두 유한한 0 이상의 숫자인지 확인합니다.

생것·익힌 것·데친 것·마른 곡물 등 원본의 대표 상태를 `label`과 `source.description`에 남깁니다. 예를 들어 흑미밥 계산 예시는 익힌 쌀밥 120 g, 마른 흑미 10 g, 계산용 물 20 g을 각각의 성분값에 적용합니다. 이것은 조리 후 무게 변화까지 검증한 실제 레시피가 아닙니다. 물 항목은 공식 식품 분석 행 대신 고형물·당류를 더하지 않는 계산용 0값으로 명시합니다.

수집한 원본 파일의 SHA-256은 다음과 같습니다.

| 원본 | SHA-256 |
| --- | --- |
| 식약처 조리식품 `식품영양성분DB_음식.xlsx` | `60263f699ffe1994ce19b83eda007cc8cf10b9f8efaa69a71968db44375fd0e8` |
| 식약처 원재료 원본 | `b0ec079bb2c91ebbe9b45f08c4dfc402291227355bae3cc95278c59846f548dc` |
| USDA `FoodData_Central_sr_legacy_food_csv_2018-04.zip` | `b80817294b8850530aaedf2e515c02593b1824f763a0ff356e5c2081643e6fd0` |

원본 파일 전체와 식약처 다운로드에 사용된 불투명한 다운로드 키는 저장소에 포함하지 않습니다. 갱신할 때는 공식 자료를 다시 확보하고, 보존된 식품코드/FDC ID·대표 상태·기준 단위·네 영양값을 대조한 뒤 각 행의 기준일을 갱신합니다. 새 원본은 기존 SHA-256과 다를 수 있으므로 갱신 기록도 함께 남깁니다.

## 계산 흐름

1. [RecommendedMeals.tsx](../src/components/RecommendedMeals.tsx)가 현재 선택한 **최종 표시 식단**을 [MealNutrition.tsx](../src/components/MealNutrition.tsx)에 전달합니다. 끼니 전환이나 최종 메뉴 변경 뒤 같은 입력에서 다시 계산합니다. 식단 관리의 두 참고 화면은 [diet/page.tsx](../src/app/diet/page.tsx)에서 선택한 날짜의 추천 식단을, 리포트는 [diet/report/page.tsx](../src/app/diet/report/page.tsx)에서 각 끼니의 `item.final`을 같은 컴포넌트에 전달합니다.
2. [estimateMealNutrition](../src/lib/mealNutrition.ts)은 `main`, `riceType`, `soup`, `sides`를 모아 앞뒤 공백을 제거하고 **그 결과가 정확히 같은 음식명**만 한 번 계산합니다. 빈 항목과 명시적인 `국 생략`, `밥 생략`, `없음` 등은 더하지 않습니다. 죽·덮밥처럼 밥을 포함한 주메뉴에 빈 `riceType`을 대신할 밥을 만들어 넣지 않습니다.
3. 음식명은 등록된 계산 예시에만 연결합니다. 이름 정규화와 명시적 별칭을 지원하지만, 알 수 없는 음식을 검색 유사도나 임의의 기본 음식으로 대체하지 않습니다. 정규화는 매칭에 쓰며, 서로 다른 표시 이름을 임의로 합치는 기준은 아닙니다.
4. 일치하는 식약처 조리식품 항목이 있으면 `100 g당 값 × 계산용 음식 무게 / 100`을 사용합니다. 음식 무게는 계산 예시의 재료 무게 합입니다. 해당 조리식품 자료가 없으면 예시에 등록된 재료별 `100 g당 값 × 재료 무게 / 100`을 합산합니다.
5. 계산 가능한 음식들의 네 영양값을 더합니다. 원본 식단, 추천 규칙, 치료·개인화 설정, 실제 기록, 기존 `nutrient` 비율과 `nutritionUnavailable` 플래그는 변경하지 않습니다. 추정 기능은 기존 플래그와 독립적으로 동작합니다.

상단 kcal는 성분 자료의 열량을 합산한 값입니다. 그래프의 분모는 `탄수화물 g × 4 + 단백질 g × 4 + 지방 g × 9`이고, 각 영양소의 환산 열량을 이 분모로 나눕니다. 따라서 **그래프는 g의 비율이나 하루 목표 달성률이 아닙니다.** 공식 자료의 총열량은 식품별 환산 방식 등에 따라 이 4/4/9 합계와 다를 수 있습니다. 화면의 수치는 표시할 때 반올림하며, 내부 계산에는 원래 합계를 사용합니다.

## 표시 상태와 추정의 한계

| 상태 | 표시 | 해석 |
| --- | --- | --- |
| `complete` | 예상 열량·추정치·그래프와 영양소 수치 | 표시 음식이 모두 계산 항목에 연결됨. 정확한 실측값이라는 뜻은 아님 |
| `partial` | 확인된 음식의 예상 열량·일부 음식 제외·계산한 음식 개수 | 알려진 음식만 합산한 부분값. 제외 음식은 계산 기준 영역에 표시 |
| `unavailable` | 대시와 확인하지 못한 음식 안내 | 합계 없음. 임의의 0 kcal나 영양 비율을 만들지 않음 |

주메뉴가 비어 있으면 `주메뉴 미정`을 남깁니다. 반찬만 계산되더라도 완전한 한 끼 합계로 표시하지 않습니다. 실제 0값인 계산용 물은 데이터 미확인 상태와 구분하며, 비율 계산에서 0으로 나누지 않습니다.

계산 예시의 재료·무게는 모델링 가정입니다. 맞춤 조리법, 식사량 안내, 임상적 섭취 목표 또는 영양적으로 동등한 대체식을 뜻하지 않습니다. 실제 조리 재료·브랜드·수분·기름·양념·먹는 양과 차이가 있으며, 사용자가 피하는 재료가 계산 예시에 포함될 수도 있습니다. 최종 음식명이 같더라도 개인화된 실제 조리법의 재료 차이까지 자동 반영하지 않습니다. 대표 상태와 가정 재료를 출처 영역에 함께 표시하는 이유입니다.

## 화면과 검증 기록

그래프는 장식 요소로 `aria-hidden` 처리하고, 동일한 영양소명·g·열량 비율을 `<dl>` 텍스트로 제공합니다. 색상만으로 값을 구분하지 않습니다. 계산 기준량·가정 재료·대표 성분 자료는 접어서 표시하며, 430px 이하에서는 g과 비율을 두 줄로 배치합니다. 스타일은 `mealNutrition` 전용 클래스와 라이트·다크 색상으로 한정합니다.

2026-09-08에 확인한 범위는 다음과 같습니다.

- [mealNutrition.test.ts](../src/lib/mealNutrition.test.ts)의 신규 테스트 20개: 공식 수치의 분량 환산·합산, 익힌/생 재료 구분, 4/4/9 분모, 중복 음식, 죽의 밥 중복 방지, 누락·비정상값·0값, 원본 식단과 기존 플래그 보존을 확인했습니다. 20개는 하위 테스트를 포함한 수입니다.
- 그중 연간 기본 식단과 대표적인 선호·개인화 변경을 포함한 **1,455끼**를 검사했습니다. 이 범위의 계산 가능성과 입력 보존을 확인한 것이며, 모든 사용자 조합이나 임상적 적합성을 검증했다는 뜻은 아닙니다.
- 320px·390px 화면과 큰 글자 모드에서 영양 그래프와 수치 배치를 확인했습니다. 실제 식단 팝업의 아침 약 **429 kcal**에서 점심 약 **527 kcal**로 전환할 때 수치가 바뀌는 동작도 확인했습니다. 이 값은 검증에 사용한 식단의 결과입니다.
