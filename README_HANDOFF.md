# 운영 인수인계 문서

## 1) 설치/실행
```bash
npm install
npm run dev
```

브라우저에서 `http://localhost:3000` 접속

## 2) 빌드 확인
```bash
npm run build
```

## 3) .env.local 필수 키(이름만)
다음 키가 있어야 Supabase 연결이 됩니다.

- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`

값 자체는 문서에 기록하지 마세요.

## 4) 테마 초기화 방법
라이트/다크 토글 저장값을 초기화하려면 브라우저 콘솔에서 아래를 실행하세요.

```js
localStorage.removeItem('theme');
```

저장값이 없으면 기본은 라이트 모드입니다.

## 5) 개발 서버 잠금/포트 충돌 해결
1. 실행 중인 터미널에서 `Ctrl + C`로 먼저 종료
2. 그래도 남아 있으면 아래로 정리

```bash
pkill -f "next dev"
```

필요하면 다시 `npm run dev` 실행

## 6) 수동 체크리스트
- `/treatment`
  - 단계 추가/수정/삭제/위로/아래로 이동
  - 진행중 상태 1개만 유지
  - 단계 이름/순서 검증 및 순서 중복 안내(한글)
- 테마
  - 기본 라이트 시작
  - 토글 즉시 반영
  - 새로고침 후 유지
- 에러 안내
  - 사용자 화면에 영문 DB 에러 원문이 노출되지 않는지 확인

## 7) 음식 검색·맞춤 정보 회귀 검증

Node.js 22.6 이상에서 새 패키지 없이 실행합니다.

```bash
npm test
npm run lint
npm run build
```

검색어 보존·유사 음식, 최근 2개월 및 기사 중복, 식사 맞춤 조합을 검증합니다. 구현 배경과 확인 항목은 [환자 중심 사용성 개선](docs/patient-experience.md)을 참고하세요.

식사 맞춤은 기존 사용자 메타데이터 `iamfine.foodPersonalization`에 저장되며 DB 마이그레이션이 필요하지 않습니다. 로그인 후 `/profile`에서 저장·선택 해제·재방문을 확인하세요.

## 8) 운영 배포

`main` 브랜치 푸시는 기존 Vercel GitHub 연결을 통해 운영 배포됩니다. GitHub 커밋 상태의 `Vercel – iamfine` 성공과 운영 주소 응답을 모두 확인하세요.

운영 주소: https://iamfine-three.vercel.app

## 9) 식단 추천과 화면 디자인

- 식단 메인은 아침·점심·저녁 버튼 3개를 모바일에서도 한 줄로 표시합니다. `src/components/RecommendedMeals.tsx`의 native `<dialog>`에서 선택한 추천 식단을 보여 주고, 조리법·식사량·영양 구성은 펼쳐서 확인합니다. 추천 화면의 끼니별 기록 링크는 제거했으며, 식사 기록은 식단 관리에서 이용합니다.
- 모바일은 오늘의 말씀 → 식사 선택 → 다음 진료 순서로 배치합니다. 데스크톱은 다음 진료를 말씀 옆에 표시합니다. 맞춤 설정 링크는 식단 설정 안에 두고, 모바일 상단의 글자 크기 전환 버튼은 간결하게 표시합니다.
- 320px와 큰 글자 모드의 식사 기록 버튼은 글자가 겹치지 않도록 배치합니다. 식단 팝업은 높이가 짧은 가로 화면에서도 본문을 읽고 스크롤할 수 있도록 여백을 줄이고 화면 안전 영역을 반영합니다.
- 식단 팝업을 열면 본문을 현재 위치에 고정하고, 닫으면 이전 스타일·스크롤 좌표·식사 선택 버튼 포커스를 복원합니다. 팝업 안에서 시작한 드래그가 배경에서 끝나더라도 닫히지 않으며, 배경에서 시작한 클릭으로 닫습니다.
- 추천 화면의 오늘의 말씀은 메인 상단에 항상 표시하며 별도의 접기 탭을 두지 않습니다. 건강 소식은 기본적으로 접혀 있으며, 더보기에는 표시하지 않습니다.
- 말씀 본문은 추천 화면의 `h1`으로 표시합니다. `src/lib/dailyVerse.ts`의 24개 구절을 한국 날짜 기준으로 순환합니다. [대한성서공회 개역한글판](https://bible.bskorea.or.kr/bible/KRV/PSA.23)의 해당 절 전체를 그대로 사용하며, 의역·문장 축약·현대식 맞춤법 변경을 하지 않습니다. 번역본과 저작자 표시, 한국어 본문 출처, 자정과 탭 복귀 시 갱신 동작을 유지합니다. 사용 기준은 [대한성서공회 개역한글판 안내](https://www.bskorea.or.kr/bbs/board.php?bo_table=copyright_faq&wr_id=5)를 참고합니다.
- 공통 색상·버튼은 `src/app/globals.css`의 `--ui-*` 토큰을 사용합니다. 흰색 바탕과 차분한 파랑을 중심으로 구성하며, 건강 소식은 `--ui-news-*` 토큰을 사용합니다. [강북삼성병원](https://main.kbsmc.co.kr/main/main.do)과 [Apple 건강](https://www.apple.com/health/)의 목적별 탐색 구조, 짧은 제목과 여백 활용을 참고했습니다.
- 내 정보의 카드 여백은 `profileSection`, 입력란은 `profileInput`, 선택 항목은 `profileChoice`에서 관리합니다. 좁은 화면과 큰 글자 모드에서 긴 선택 항목이 한 열로 표시되는지 확인하세요.
- 320px 화면과 큰 글자 모드에서 식단 버튼 3개가 한 줄을 유지하고 가로 스크롤이 생기지 않는지 확인하세요. 각 버튼의 식단, 팝업 안의 끼니 전환, 닫기 버튼·배경 클릭·Escape, 닫은 뒤 원래 버튼으로 포커스와 페이지 스크롤이 복원되는지도 확인하세요.
- 높이가 짧은 가로 화면에서 팝업 본문 끝까지 스크롤되고 닫기 버튼이 보이는지, 화면 안전 영역에 내용이 가리지 않는지 확인하세요. 팝업 배경의 스크롤 정지와 내부에서 배경으로 드래그했을 때 팝업이 유지되는 동작도 확인하세요.
- 식단 관리에서 날짜·끼니 선택, 음식 추가와 식사 기록 저장, 복용 약 체크가 유지되는지 확인하세요. 더보기의 진료 일정과 화면·계정 설정, 내 정보의 5개 탭, 밝게/어둡게 보기와 큰 글자 모드도 함께 확인하세요.
- 7절의 `npm test`, `npm run lint`, `npm run build` 검증은 계속 적용합니다. `npm test`에는 말씀의 한국 자정·월말·연말·윤일 전환 검증이 포함됩니다.

## 10) 식단별 예상 영양 구성

- 추천 팝업의 영양 구성은 `MealNutrition`에서 현재 표시 식단을 계산해 예상 kcal, 탄수화물·단백질·지방 g과 열량 비율을 보여 줍니다. 기존 추천 규칙·`nutrient`·`nutritionUnavailable`·식사 기록·상단 말씀 동작은 변경하지 않습니다.
- 식단 관리의 기록일 추천 식단 팝업, 식사 기록 살펴보기의 영양 참고 정보, 리포트의 최종 추천 식단 영양 구성에도 같은 컴포넌트를 사용합니다. 끼니별로 펼쳐 확인하며, 각 화면의 최종 추천 식단 예시를 계산합니다. 실제 식사 기록의 영양 분석값은 아닙니다.
- 식약처·USDA의 100 g 기준 성분값과 별도 계산용 분량을 사용합니다. 실제 섭취량·개인 권장량·맞춤 조리법이 아니며, 회피 재료와 실제 조리 방식에 따라 달라질 수 있습니다. 계산 기준량·가정 재료·출처는 팝업에서 펼쳐 확인합니다.
- 일부 음식만 계산되면 부분값임을 표시하고, 자료가 없으면 0 kcal 대신 확인 불가 상태를 표시합니다. 그래프의 4/4/9 환산 열량 합계는 성분 자료의 공식 총열량과 다를 수 있습니다.
- 데이터 출처와 원본 SHA-256, 갱신 방법, 계산 흐름, 추정 한계, 신규 테스트 20개와 1,455끼 검증 범위는 [식단별 예상 영양 구성](docs/meal-nutrition.md)을 참고하세요. 전체 테스트 83개·전체 린트·빌드가 통과했으며, 리포트의 최종 통합도 타깃 ESLint와 빌드로 확인했습니다.
- 변경 후 320px·390px와 큰 글자·다크 모드, 끼니 전환에 따른 값 변경, 부분 매칭과 미확인 화면, 출처 펼치기를 확인하세요. 추천 팝업·식단 관리·리포트에 전달된 최종 메뉴와 영양값도 확인합니다. 식사 기록 저장과 메인 상단 말씀·자정 갱신에 대한 기존 회귀 검증을 계속 적용합니다.
