# 운영 인수인계 문서

## 1) 설치/실행
```bash
npm install
npm run dev
```

브라우저에서 `http://localhost:3000` 접속

## 2) 빌드 확인
```bash
npm run build
```

## 3) .env.local 필수 키(이름만)
다음 키가 있어야 Supabase 연결이 됩니다.

- `NEXT_PUBLIC_SUPABASE_URL`
- `NEXT_PUBLIC_SUPABASE_ANON_KEY`

값 자체는 문서에 기록하지 마세요.

## 4) 테마 초기화 방법
라이트/다크 토글 저장값을 초기화하려면 브라우저 콘솔에서 아래를 실행하세요.

```js
localStorage.removeItem('theme');
```

저장값이 없으면 기본은 라이트 모드입니다.

## 5) 개발 서버 잠금/포트 충돌 해결
1. 실행 중인 터미널에서 `Ctrl + C`로 먼저 종료
2. 그래도 남아 있으면 아래로 정리

```bash
pkill -f "next dev"
```

필요하면 다시 `npm run dev` 실행

## 6) 수동 체크리스트
- `/treatment`
  - 단계 추가/수정/삭제/위로/아래로 이동
  - 진행중 상태 1개만 유지
  - 단계 이름/순서 검증 및 순서 중복 안내(한글)
- 테마
  - 기본 라이트 시작
  - 토글 즉시 반영
  - 새로고침 후 유지
- 에러 안내
  - 사용자 화면에 영문 DB 에러 원문이 노출되지 않는지 확인

## 7) 음식 검색·맞춤 정보 회귀 검증

Node.js 22.6 이상에서 새 패키지 없이 실행합니다.

```bash
npm test
npm run lint
npm run build
```

검색어 보존·유사 음식, 최근 2개월 및 기사 중복, 식사 맞춤 조합을 검증합니다. 구현 배경과 확인 항목은 [환자 중심 사용성 개선](docs/patient-experience.md)을 참고하세요.

식사 맞춤은 기존 사용자 메타데이터 `iamfine.foodPersonalization`에 저장되며 DB 마이그레이션이 필요하지 않습니다. 로그인 후 `/profile`에서 저장·선택 해제·재방문을 확인하세요.

## 8) 운영 배포

`main` 브랜치 푸시는 기존 Vercel GitHub 연결을 통해 운영 배포됩니다. GitHub 커밋 상태의 `Vercel – iamfine` 성공과 운영 주소 응답을 모두 확인하세요.

운영 주소: https://iamfine-three.vercel.app

## 9) 모바일 식단 참고와 식사 기록

- 하단 메뉴는 `오늘의 식단` · `식사 기록` · `더보기`로 표시합니다. 공통 색상은 `src/app/globals.css`의 `--ui-*` 토큰으로 관리하며, 따뜻한 흰색 바탕과 초록색을 사용합니다. 다크 모드와 큰 글자 모드를 유지합니다.
- 아침·점심·저녁 버튼 3개는 모바일에서도 한 줄로 표시합니다. `src/components/MealIllustration.tsx`의 컬러 SVG 음식 그림과 대표 메뉴를 함께 보여 주고, 해당 끼니에 먹음·안 먹음 기록이 있으면 `기록 있음`을 표시합니다. 그림은 끼니 구분용이며 실제 추천 메뉴 사진은 아닙니다.
- `src/components/RecommendedMeals.tsx`의 native `<dialog>`는 메뉴를 먼저 보여 주고, 조리법·식사량·영양 구성은 펼쳐 확인합니다. 비슷한 음식 선택은 식사 기록의 `변경`으로 모았습니다. 복약 체크는 메뉴 아래에 둡니다. 오늘과 과거 날짜에는 `먹은 음식 체크` 버튼으로 선택한 날짜·끼니의 기록 화면에 연결하며, 미래 식단에는 이 버튼을 표시하지 않습니다.
- 식사 기록은 음식 행을 한 번 눌러 먹음 표시를 켜고 끕니다. 눈에 보이는 `변경` 버튼에서 실제로 먹은 비슷한 메뉴를 고르면 음식 이름을 바꾸고 먹음으로 표시합니다. `다른 음식 추가`를 펼치면 검색창에 음식 이름을 직접 입력할 수도 있습니다. 날짜는 입력란과 앞뒤 이동 버튼으로 선택합니다. 비슷한 음식은 영양과 섭취량이 같다는 뜻이 아니며, 추천 메뉴를 그대로 먹었다고 자동 기록하지 않습니다.
- `안 먹음`은 각 음식의 변경 영역에서 선택합니다. `모두 먹었어요` · `모두 안 먹었어요` · `체크 해제`는 `한 번에 체크하기` 안에 모았습니다. 체크 해제는 먹음·안 먹음 상태만 지우며, 바꾼 음식 이름과 직접 추가한 음식은 유지합니다. `기록 저장` 버튼으로 해당 날짜의 식사 기록을 저장합니다.
- 일상 기록 화면에서 추천 메뉴 일치 점수와 중복 영양 분석 영역을 제거했습니다. 영양 정보는 추천 식단 팝업과 리포트에서 확인합니다. 반복 안내를 줄이고 복약 기록은 접어서 표시합니다.
- 모바일은 오늘의 말씀 → 식사 선택 → 다음 진료 순서입니다. 말씀은 상단에 항상 표시하며 별도의 접기 탭을 두지 않습니다. 건강 소식과 식단 맞춤 설정은 기본적으로 접혀 있고, 건강 소식은 더보기에 표시하지 않습니다.
- 말씀 본문은 추천 화면의 `h1`으로 표시합니다. `src/lib/dailyVerse.ts`의 24개 구절을 한국 날짜 기준으로 순환합니다. [대한성서공회 개역한글판](https://bible.bskorea.or.kr/bible/KRV/PSA.23)의 해당 절 전체를 그대로 사용하며, 의역·문장 축약·현대식 맞춤법 변경을 하지 않습니다. 번역본과 저작자 표시, 한국어 본문 출처, 자정과 탭 복귀 시 갱신 동작을 유지합니다. 사용 기준은 [대한성서공회 개역한글판 안내](https://www.bskorea.or.kr/bbs/board.php?bo_table=copyright_faq&wr_id=5)를 참고합니다.
- 팝업을 열면 배경 스크롤을 고정하고, 닫으면 기존 스타일·스크롤 좌표·열었던 버튼 포커스를 복원합니다. 팝업 안에서 시작해 배경에서 끝나는 드래그로는 닫히지 않습니다. 끼니 전환, 닫기·배경 클릭·Escape, 짧은 가로 화면의 내부 스크롤과 안전 영역은 회귀 확인 대상입니다.
- 내 정보의 카드 여백은 `profileSection`, 입력란은 `profileInput`, 선택 항목은 `profileChoice`에서 관리합니다. 좁은 화면·큰 글자에서 긴 항목과 버튼이 겹치지 않는지, 날짜·끼니 전환과 복약 체크가 유지되는지 확인하세요.

이번 변경에서 `npm test` 106개, 전체 린트와 빌드가 통과했습니다. 로컬 브라우저에서 320px·390px, 큰 글자·다크 모드와 음식 변경·직접 추가·저장·체크 해제·새로고침 후 기록 복원을 확인했습니다. 브라우저 확인은 가상 계정과 메모리 저장을 사용하는 별도 로컬 모의 서버로 진행했으며, 실제 계정 데이터와 DB 스키마는 변경하지 않았습니다. 이 확인은 실제 서버 동기화 검증을 대신하지 않습니다. 짧은 가로 화면과 팝업 닫기 시 스크롤·포커스 복원도 변경 시 계속 확인하세요.

## 10) 식단별 예상 영양 구성

- 추천 팝업의 영양 구성은 `MealNutrition`에서 현재 표시 식단을 계산해 예상 kcal, 탄수화물·단백질·지방 g과 열량 비율을 보여 줍니다. 기존 추천 규칙·`nutrient`·`nutritionUnavailable`·식사 기록·상단 말씀 동작은 변경하지 않습니다.
- 식사 기록 화면에서 여는 기록일 추천 식단 팝업과 리포트의 최종 추천 식단 영양 구성에도 같은 컴포넌트를 사용합니다. 끼니별로 펼쳐 확인하며, 각 화면에 표시된 추천 식단을 계산합니다. 실제 먹은 음식 기록의 영양 분석값은 아닙니다. 중복되던 식사 기록 살펴보기의 영양 참고 영역은 제거했습니다.
- 식약처·USDA의 100 g 기준 성분값과 별도 계산용 분량을 사용합니다. 실제 섭취량·개인 권장량·맞춤 조리법이 아니며, 회피 재료와 실제 조리 방식에 따라 달라질 수 있습니다. 계산 기준량·가정 재료·출처는 팝업에서 펼쳐 확인합니다.
- 일부 음식만 계산되면 부분값임을 표시하고, 자료가 없으면 0 kcal 대신 확인 불가 상태를 표시합니다. 그래프의 4/4/9 환산 열량 합계는 성분 자료의 공식 총열량과 다를 수 있습니다.
- 데이터 출처와 원본 SHA-256, 갱신 방법, 계산 흐름, 추정 한계, 신규 테스트 20개와 1,455끼 검증 범위는 [식단별 예상 영양 구성](docs/meal-nutrition.md)을 참고하세요. 문서의 테스트 수는 영양 기능 도입 당시 기준이며, 이번 변경의 검증 결과는 9절을 참고하세요.
- 변경 후 320px·390px와 큰 글자·다크 모드, 끼니 전환에 따른 값 변경, 부분 매칭과 미확인 화면, 출처 펼치기를 확인하세요. 추천 팝업·식단 관리·리포트에 전달된 최종 메뉴와 영양값도 확인합니다. 식사 기록 저장과 메인 상단 말씀·자정 갱신에 대한 기존 회귀 검증을 계속 적용합니다.

## 11) 복약 배지와 추천·검색 안정성

- 식사 선택 카드의 복약 상태는 우측 상단에 약 아이콘과 `복약`으로 표시합니다. 배지는 카드 높이에 영향을 주지 않으며, 스크린리더에는 예정 약 개수 또는 체크 완료 개수를 전달합니다. 실제 복약 체크는 기존 팝업에서 수행합니다.
- 식단 엔진은 날짜·치료 단계별 기본 메뉴를 최대 128개까지 메모리에 재사용합니다. 반환 시 중첩 배열과 영양 객체까지 복사하고, 선호·증상·회피 재료 등 개인별 조정은 매번 적용합니다. 개인별 결과는 이 공통 캐시에 저장하지 않습니다. 추천에 사용되지 않던 지난달 점수 계산도 제거했습니다.
- 건강소식은 저장된 기사를 유지하면서 새로고침합니다. 정상 응답은 1시간, 일부 출처 실패는 5분 후 갱신하며, 전체 실패는 자동 재시도 간격을 최소 1분으로 제한합니다. 화면 복귀·네트워크 복구 시 재확인하고, 요청은 15초 안에 종료합니다. 계정과 암종별 세션 캐시를 분리하고 계정 전환 시 진행 중 요청을 취소합니다. 최근 두 달 필터는 저장된 기사에도 다시 적용합니다.
- 식당 검색은 지역 입력을 확인하고, 외부 조회에 시간 제한과 요청 취소를 적용합니다. 빠르게 다시 검색하면 이전 응답이 새 결과를 덮어쓰지 않습니다. 진단·치료 단계·동반 질환을 검색 API에 전달하지 않고 선택된 음식 관련 용어만 사용합니다.
- 식당 후보는 네이버 지도 장소 ID가 있는 링크에서만 추출하며, 기사 제목에서 이름을 추측하지 않습니다. 동명 지점은 장소 ID로 구분합니다. 지도 등록 여부는 현재 영업이나 개인별 식사 적합성을 보증하지 않습니다. 일부 실패·전체 실패·빈 결과를 구분하고, 지역과 음식 조건을 보존한 네이버·카카오 지도 검색 링크를 제공합니다. 외부 검색 페이지 형식이 달라지거나 접근이 제한되면 목록 대신 지도 검색을 이용할 수 있습니다.
- 식당 조회는 동시에 최대 4개 검색어, 출처당 5초, 좌표의 지역명 변환은 3초로 제한합니다. 실제 장소를 찾은 공개 검색 결과만 2분간 최대 32개 재사용하고, 좌표·프로필·실패 응답은 캐시하지 않습니다.
- 새 패키지나 DB 스키마 변경은 없습니다. 회귀 테스트에는 기본 식단 객체 변경·개인화 격리, 뉴스 캐시·실패·취소, 식당 출처 실패·위치 확인·장소 ID·지역을 보존한 지도 링크가 포함됩니다.
- 이 추가 변경에서 테스트 136개, 전체 린트와 운영 빌드가 통과했습니다. 복약 없음·예정·일부 완료·전체 완료는 서버 렌더링으로 확인했습니다. 실제 공개 출처를 이용한 로컬 건강소식 API는 200 및 새 클라이언트 검증 통과, 식당 API는 지역 누락 400과 외부 검색 실패 503·지도 대체 링크를 확인했습니다. 브라우저 연결을 사용할 수 없어 이번 추가 변경의 모바일 화면 재확인은 수행하지 못했습니다.
